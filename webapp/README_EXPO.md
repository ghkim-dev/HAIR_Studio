# 박람회 부스 운영 안내 — AI 헤어 스타일 체험

관람객이 사진을 찍고 스타일을 고르면, Open AI Service Hub의 언어·비전·이미지 편집 모델이
**용어 이해 → 계획 → 체크리스트 → 생성 → 검증 → 반성** 과정을 거쳐 새 헤어스타일을 만들어 줍니다.
진행 과정이 화면에 그대로 보이므로, 우리 인프라(H100 GPU · Open AI Service Hub)가 일하는 모습을 시연할 수 있습니다.

## 1. 장비

| 장비 | 권장 |
|---|---|
| 노트북/미니PC | Windows 10/11, Python 3.10 이상, Chrome |
| 웹캠 | 1080p, 모니터 위 눈높이에 설치 (정면 촬영) |
| 모니터 | 24인치 이상 가로형(1920×1080) — 터치 모니터면 가장 좋음 |
| 조명 | 얼굴 정면에서 부드러운 조명 (역광 피하기, 배경은 밝은 단색 벽) |
| 네트워크 | Hub(open.hasa.re.kr) 접속 가능한 유선 랜 권장. QR로 결과를 받게 하려면 관람객 휴대폰이 접속할 수 있는 주소 필요(아래 3번) |

## 2. 설치와 실행

```bat
cd %USERPROFILE%\Downloads\hair_studio
.venv\Scripts\activate
pip install -r requirements.txt
python -m webapp.server
```

`AI 헤어 스타일 체험 서버: http://localhost:8000` 이 나오면 키오스크 모드로 화면을 엽니다.

```bat
start chrome --kiosk --use-fake-ui-for-media-stream http://localhost:8000
```

- `--kiosk`: 주소창 없이 전체화면 (종료는 `Alt+F4`)
- `--use-fake-ui-for-media-stream`: 카메라 권한 팝업을 자동 허용 (부스 PC 전용으로만 사용)
- 처음 한 번은 `.env`에 개발키(`OASH_API_KEY`)가 들어 있어야 합니다. 시작 전에 `python hair_studio.py models`로 `개발키 정상 ✔`을 확인하세요.

## 3. 설정 (`.env`에 추가)

| 항목 | 기본값 | 설명 |
|---|---|---|
| `EXPO_PORT` | 8000 | 서버 포트 |
| `EXPO_WORKERS` | 2 | 동시에 처리할 관람객 수. 나머지는 대기열(순번 표시) |
| `EXPO_ROUNDS` | 2 | 생성→검증→반성 최대 반복 수 (줄이면 빨라짐) |
| `EXPO_CANDIDATES` | 2 | 라운드당 후보 이미지 수 |
| `EXPO_THRESHOLD` | 0.8 | 이 점수 이상이면 바로 완성 |
| `EXPO_RETENTION_MIN` | 30 | 사진·결과 자동 삭제까지 분 |
| `EXPO_IDLE_SEC` | 90 | 결과 화면에서 손대지 않으면 첫 화면으로 돌아가는 시간 |
| `EXPO_FAST` | auto | 빠른 모드. `auto`면 `OASH_MAX_CONCURRENCY=1`(개발키)일 때 켜짐. `1`/`0`으로 강제 |
| `EXPO_PUBLIC_URL` | (자동) | QR에 넣을 주소. 휴대폰이 부스 PC에 접속할 수 있는 주소로 지정. 예: `http://192.168.0.20:8000` |

**QR 다운로드 주의**: 관람객 휴대폰은 보통 부스 PC와 다른 망(LTE·행사장 와이파이)에 있습니다.
- 부스 전용 와이파이 공유기를 두고 PC와 휴대폰을 같은 망에 연결하거나,
- 서버를 기관 내 공개 주소(예: 리버스 프록시)로 노출한 뒤 `EXPO_PUBLIC_URL`에 그 주소를 넣으세요.
- 둘 다 어렵다면 QR 대신 스태프가 화면을 사진으로 찍어 주는 방식으로 운영해도 됩니다.

## 4. 빠른 모드 (동시 1건 키용)

개발키는 동시 요청이 1건이라 모든 호출이 줄을 섭니다. 그래서 갤러리에서 고른 스타일은 **용어집 속성만으로** 계획·체크리스트·프롬프트·반성을 만들고, Hub에는 **후보마다 이미지 편집 1회 + 비전 검증 1회**만 보냅니다.

| | 전체 모드 | 빠른 모드 |
|---|---|---|
| 사진 관찰·용어 분석·계획·체크리스트·프롬프트 작성 | 언어·비전 모델 5~6회 | 0회 (용어집 규칙) |
| 후보 1장 | 편집 1 + 검증 1 | 편집 1 + 검증 1 |
| 반성 | 언어 모델 1회 | 0회 (실패 항목 → 다음 프롬프트) |
| 2라운드 × 후보 2장 | 약 15회 | **8회** (1라운드에 끝나면 4회) |

- 갤러리 스타일에 덧붙인 말("추가 요청")은 원문 그대로 프롬프트에 붙습니다.
- 갤러리에 없는 말만 적은 경우(용어집에서 용어를 못 찾으면)는 자동으로 전체 모드로 처리됩니다.
- 동시 한도가 큰 키를 쓰게 되면 `.env`에 `OASH_MAX_CONCURRENCY`를 그 값으로, `EXPO_FAST=0`으로 두면 전체 파이프라인을 시연할 수 있습니다.

## 4-1. 처리량 가늠하기

한 명당 걸리는 시간 ≈ (언어 모델 호출 4~6회) + (라운드 × 후보 × 이미지 편집 1회) + (라운드 × 후보 × 비전 검증 1회).

1. 행사 전날 실제 Hub로 3~5번 체험해 보고 터미널/화면의 경과 시간을 잽니다 (예: 평균 90초).
2. 시간당 처리 인원 ≈ `3600 ÷ 1인당 시간 × EXPO_WORKERS` (예: 3600 ÷ 90 × 2 = 약 80명).
3. 줄이 길면 `EXPO_ROUNDS=1`, `EXPO_CANDIDATES=2`로 낮추고, 한가하면 라운드를 늘려 품질을 높입니다.
4. **키의 동시 요청 한도가 처리량을 결정합니다.** 개발키는 동시 1건이라, 모든 Hub 호출(언어·비전·이미지)이 한 줄로 처리됩니다. 이때 `EXPO_WORKERS`나 후보 수를 늘려도 빨라지지 않고 대기만 길어집니다.
   - 박람회에는 동시 한도가 큰 **실증키/운영키**를 쓰고, `.env`의 `OASH_MAX_CONCURRENCY`를 그 한도에 맞추세요 (예: 4).
   - 프로그램이 이 값을 넘겨 보내지 않으므로 429(동시 한도 초과)가 나지 않습니다. 그래도 429/503이 오면 서버가 알려준 시간만큼 기다렸다 재시도합니다.

## 5. 개인정보 안내 (화면에 표시되는 문구와 동일)

- 사진은 체험용 합성에만 사용하고, 부스 서버의 `output\expo\` 폴더에만 저장합니다.
- `EXPO_RETENTION_MIN`분(기본 30분) 뒤 자동 삭제되며, 결과 화면의 **내 사진 삭제**로 즉시 지울 수 있습니다.
- 저장 전에 사진의 EXIF(촬영 위치·기기 정보)를 제거합니다.
- 모델 호출은 Open AI Service Hub로만 나갑니다.
- 동의 체크 없이는 촬영 단계로 넘어갈 수 없고, 서버도 동의 없는 요청을 거부합니다.
- 행사 종료 후 `output\expo\` 폴더를 통째로 삭제하세요.

## 6. 문제 해결

| 증상 | 조치 |
|---|---|
| “카메라를 사용할 수 없어요” | 다른 프로그램(줌 등)이 웹캠을 쓰는지 확인, Chrome을 `--use-fake-ui-for-media-stream`으로 다시 실행, 안 되면 ‘사진 파일 올리기’ |
| 진행 화면에서 멈춤 | 서버 터미널의 오류 확인. `개발키` 오류면 `.env` 확인, 429/503이면 잠시 대기 |
| 결과가 어색함 | 스타일 대신 왼쪽 칸에 원하는 모습을 구체적으로 적거나, `EXPO_ROUNDS`를 3으로 |
| QR이 안 열림 | `EXPO_PUBLIC_URL`이 휴대폰에서 접속 가능한 주소인지 확인 (3번) |
| 갤러리 카드에 사진이 없음 | 아래 '행사 전 준비' 2번으로 썸네일을 미리 만들어 두세요 |

## 7. 시연 없이 화면만 확인하기

```bat
python tests\test_webapp.py            :: API·진행 흐름 점검 (Hub 없이 가짜 파이프라인)
python tests\test_webapp.py --shots    :: 화면별 스크린샷 생성 (Playwright 필요)
```

## 7. 행사 전 준비 체크리스트

1. `python hair_studio.py models` → `개발키 정상 ✔` 확인
2. **갤러리 썸네일 생성** (Hub의 Qwen-Image로 163개 스타일 예시 사진을 미리 만듦. 인기 스타일부터)
   ```bat
   python tools\build_gallery.py --limit 40          :: 인기 스타일 40개 먼저
   python tools\build_gallery.py                     :: 나머지 전부 (이미 만든 건 건너뜀)
   ```
   썸네일 자체가 "용어를 속성으로 이해해 그린 결과"라 시연 소재가 됩니다. 이상한 썸네일은 지우고 `--only 허쉬컷 --force`로 다시 만드세요.
3. `python tests\eval_terms.py` → 용어 인식 회귀 테스트 통과 확인
4. 스태프가 남녀 각 2~3개 스타일로 실제 체험해 보고 1인당 시간 측정 (4번 처리량 계산)
5. 결과가 자주 어색한 스타일은 `knowledge\images\<스타일>\`에 참고 사진을 넣거나 갤러리에서 숨기기
   (용어집 `knowledge\corpus\*.json`에서 해당 항목의 `popularity`를 `"hidden"`으로 바꾸면 갤러리에서 숨겨집니다)
